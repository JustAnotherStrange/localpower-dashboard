How the Energy Profile Dashboard Works

A plain-language walkthrough of energy_profile_dashboard.html for anyone handing it off, reviewing it, or just curious what happens after you drop a file on it.

The short version: it's a single HTML file. Open it in a browser, upload a household's usage/solar spreadsheet, and it draws charts — entirely on your own computer. Nothing is uploaded to a server; there is no server.

The pipeline

Uploadhousehold drops .ods file(s)
→
Unzip & read.ods is a zip of XML
→
Classify sheetsby column headers
→
Aggregatemonthly & hourly averages
→
Draw chartsin the browser, live

A separate, optional last step — "Export" — freezes the current charts into a second, standalone HTML file to hand to the household.

What kind of file does it need?

An .ods spreadsheet (OpenDocument, the format LibreOffice/Excel export) containing NYSEG smart-meter data and/or an NREL PVWatts solar simulation. The dashboard looks at every sheet inside the file and decides what each one is by its column headers — not by trusting the sheet name alone:

Sheet contains…Treated as
Date, Net, Hour, Month Name columns, and the sheet name mentions "gas" Gas usage
Same four columns, sheet name mentions "electric" / "smart meter" / "load" Electric usage
An AC System Output (kWh) column Solar (PV) potential
Anything else Skipped, and noted in the on-page upload log

If a raw-interval sheet's name doesn't say "gas" or "electric" anywhere, a one-time pop-up simply asks which one it is — it never guesses silently.

What it deliberately ignores

  • Pivot-table / "Avg Hourly … by Month" sheets. These are frozen snapshots of whatever single month was selected in a dropdown when the source spreadsheet was saved — not a real 12-month average. The dashboard always recomputes its own averages from the raw interval data instead of trusting one of these.
  • PVWatts' own weather columns (Ambient/Cell Temperature). The electric and gas sheets carry their own Weather column (°F, per row) used for the temperature charts instead.

What it computes

  • Monthly totals — usage per calendar month, averaged down to a single representative year even if the export spans multiple years unevenly.
  • Hourly patterns — average usage by hour-of-day, per month, so load and solar potential can be compared hour-by-hour.
  • Temperature trend — average usage at each outdoor temperature (from the sheet's Weather column), lightly smoothed into one line per fuel.
  • Cold-weather share — what portion of a home's usage happens on days below freezing, versus what portion of the year is that cold.

What you get on screen

  • Hourly load vs. hourly onsite PV potential, month by month (with a slider)
  • Monthly electricity usage vs. modeled PV potential
  • Monthly gas usage
  • Usage-vs-outdoor-temperature trend lines (electric & gas)
  • A cold-weather plain-language callout stat

Each chart only appears once its underlying data is loaded — drop just a gas file, and only the gas-related charts populate; the rest show a simple placeholder.

Why offline, why hand-rolled parsing

The whole point is that this stays a single file a case worker can hand to a household with no install, no account, and no data ever leaving their computer. Since browsers can't unzip files or read .ods natively, the dashboard includes its own small, from-scratch ZIP reader, DEFLATE decompressor, and XML walker — instead of pulling in an external library, which would mean a network dependency or a bundling step.

Exporting a clean copy

Once at least one dataset is loaded, "Export" saves a second HTML file with the same charts and interactivity, but with the upload controls stripped out — ready to hand to a household as a finished report.
